# DÖM Running Bot

Телеграм-бот бегового клуба DÖM Running (ÖMANKÖ DÖM).

Анонсы тренировок с записью, напоминания, чек-ин на месте, личная статистика и клубные челленджи. Внешних интеграций нет — весь километраж считается из дистанций маршрутов по отметкам участников.

## Стек

aiogram 3 · SQLAlchemy 2 (async) · PostgreSQL · APScheduler · Docker

## Что умеет

**Участник:** регистрация в два шага, запись на тренировку кнопкой в анонсе, напоминания накануне в 20:00 и за 2 часа, чек-ин на месте, личная статистика, клубные челленджи месяца.

**Админ:** маршруты с текстовым описанием точек, создание тренировки в 5 шагов (с описанием и фото/гифкой), отмена с шаблонными причинами, перенос, ручная правка чек-инов, экспорт CSV, метрики клуба.

**Приватность записей:** в публичном анонсе счётчик записавшихся не показывается. Число видит только админ — в уведомлении при каждом нажатии «Иду» и в карточке тренировки.

## Локальный запуск

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env   # заполнить BOT_TOKEN, CLUB_CHAT_ID, ADMIN_IDS
export $(grep -v '^#' .env | xargs)
python -m bot.main
```

Без `DATABASE_URL` поднимется SQLite-файл в корне проекта — удобно для проверки.

## Группа или канал

Анонсы можно постить и в групповой чат, и в канал — код один и тот же, меняется только `CLUB_CHAT_ID`. Кнопка «Иду» работает в обоих случаях.

**Канал** даёт чистую ленту без болтовни: посты пишут только админы. Участники должны быть подписаны, иначе анонс не увидят.

**Группа** удобнее, если вокруг тренировок идёт обсуждение.

Комбинация: канал с привязанной группой обсуждений. Анонс автоматически уходит в неё комментарием, кнопка сохраняется и работает в обеих копиях.

Для канала: добавить бота в администраторы с правом публикации и редактирования сообщений. ID канала — переслать любой пост боту [@userinfobot](https://t.me/userinfobot), либо для публичного канала указать `@username`.

## Подготовка в Telegram

1. Создать бота у [@BotFather](https://t.me/BotFather), забрать токен.
2. В настройках бота у BotFather: `/setprivacy` → **Disable**. Без этого бот не увидит свои сообщения в группе.
3. Добавить бота в чат клуба и выдать права администратора — нужны для публикации и редактирования анонсов.
4. Узнать `CLUB_CHAT_ID`: переслать любое сообщение из чата боту [@userinfobot](https://t.me/userinfobot). У супергрупп ID отрицательный, вида `-1001234567890`.
5. Свой Telegram ID — там же, для `ADMIN_IDS`.

## Деплой на Railway

1. Залить репозиторий на GitHub.
2. В Railway: **New Project → Deploy from GitHub repo**, выбрать репозиторий. Dockerfile подхватится автоматически.
3. В том же проекте: **New → Database → PostgreSQL**. Railway сам пробросит `DATABASE_URL` в сервис бота.
4. В сервисе бота, вкладка **Variables**, добавить:

   | Переменная | Значение |
   |---|---|
   | `BOT_TOKEN` | токен от BotFather |
   | `CLUB_CHAT_ID` | `-1001234567890` |
   | `ADMIN_IDS` | `11111111,22222222` |
   | `CLUB_TZ` | `Europe/Moscow` |

5. Deploy. Таблицы создадутся при первом старте, шаблоны причин отмены засеются автоматически.

Публичный домен включать не нужно — бот работает на long polling, входящих HTTP-запросов не принимает.

**Важно:** держать ровно одну реплику. Два инстанса на long polling будут перехватывать апдейты друг у друга, а напоминания уйдут дважды.

## Первые шаги после деплоя

1. Написать боту `/start` — пройти регистрацию.
2. `/admin` → **Маршруты** → **Новый маршрут** — завести первый маршрут.
3. `/admin` → **Новая тренировка** — 4 шага и публикация в чат.

## Переменные окружения

| Переменная | Обязательна | По умолчанию | Описание |
|---|---|---|---|
| `BOT_TOKEN` | да | — | токен бота |
| `CLUB_CHAT_ID` | да | — | ID группы или канала для анонсов; для публичного канала можно `@username` |
| `ADMIN_IDS` | да | — | Telegram ID админов через запятую |
| `ADMIN_CHAT_ID` | нет | — | чат для уведомлений о записях; без него уведомления идут в личку каждому админу |
| `DATABASE_URL` | на Railway автоматически | SQLite-файл | строка подключения |
| `CLUB_TZ` | нет | `Europe/Moscow` | часовой пояс клуба |
| `EVENING_REMINDER_HOUR` | нет | `20` | час напоминания накануне |
| `CHECKIN_OPEN_MINUTES` | нет | `30` | за сколько минут открывается чек-ин |
| `CHURN_INACTIVE_DAYS` | нет | `30` | порог неактивности для метрики отвала |

## Заметки по реализации

**Дистанция берётся из маршрута по ссылке**, а не копируется в тренировку. Если отредактировать маршрут, статистика за прошлые месяцы пересчитается. Если понадобится фиксировать историю — скопировать `distance_km` и `elevation_m` в `trainings` в момент создания.

**Планировщик не хранит задачи.** Раз в минуту опрашивает базу и смотрит, кому пора слать; факт отправки пишется флагами `reminder_evening_sent` и `reminder_2h_sent` в таблице тренировок. Переживает рестарты на Railway без внешнего стора. При переносе тренировки флаги сбрасываются.

**Схема создаётся через `create_all`** при старте. Полноценных миграций нет, но в `db.py` есть список `ADDED_COLUMNS` — недостающие колонки дописываются через `ALTER TABLE` при запуске, так что обновление на живой базе не требует ручных действий. Операция идемпотентна. При более сложных изменениях (переименования, смена типов) понадобится Alembic.

**Медиа хранится как `file_id`**, а не файлом. Telegram отдаёт его при загрузке, и одну и ту же картинку можно переиспользовать без повторной заливки. Обратная сторона — `file_id` привязан к боту: при смене токена ссылки на старые медиа перестанут работать.

**FSM в памяти.** При рестарте недозаполненные формы админа теряются — на практике незаметно. Если станет мешать, есть `RedisStorage`.

**Незарегистрированный, нажавший «Иду»** в группе, получает алерт со ссылкой на бота, проходит регистрацию, и запись засчитывается автоматически через deep link.
